# 03 キーワード調査

事業の CV から出発してキーワード候補を集め、表記ゆれ・検索意図・ファネル段階・CV への近さで整理し、自サイトの規模を基準にリストA（すぐ狙える）・B（専門性を築く）・C（後回し）に分けて [04-topical-map.md](04-topical-map.md) に渡すための手順。

## 1. 目的

- CV（問い合わせ・購入・資料請求など）につながる検索需要を、ツールの実データで一覧にする（鉄則1・2）。
- 各キーワードに「表記ゆれのグループ」「検索意図とファネル段階」「CV への近さ（1-5）」を付け、自サイトの実データ（参照ドメイン数・インデックス登録済みページ数・月間の自然検索クリック数）を基準にリストA / B / C に分ける。
- この段階ではページを決めない。どのキーワードをどの URL で狙うか、既存ページと重なるかの判断は 04、SERP の詳しい分析とブリーフは [05-serp-brief.md](05-serp-brief.md) で行う。

## 2. 必要な入力データ

| データ | 入手元（ツール → 画面 → 操作） | 必須/任意 | ないときの動き方 |
|---|---|---|---|
| 事業の前提（商材、CV の定義、ターゲット、読者の悩み、競合リスト、一次情報の源泉、表現上の制約） | 作業フォルダの `seo/site-brief.md` | 必須 | [01-setup.md](01-setup.md) の初回セットアップを先に行う。CV が未定義なら「CV への近さ」列を `[要追加: CVの定義]` にして、候補の収集と表記ゆれの整理だけ進める |
| 自サイトで既に表示されているクエリ | Search Console →「検索パフォーマンス」→「検索結果」→ 期間を設定（季節性を見るなら12か月以上）→「エクスポート」→ クエリ別・ページ別のファイル（`クエリ.csv` / `ページ.csv` という名前のことが多い） | 既存サイトは必須。公開前・公開直後のサイトはデータがないので使わない | 既存サイトはエクスポートを依頼し、届くまで「既存の対応URL」列を `[要追加: GSCのクエリ×ページ]` にする。新規サイトは site-brief・競合リスト・キーワードツールだけでシードを作る |
| キーワード候補と検索ボリューム・難易度 | Ahrefs → Keywords Explorer → 国を日本にしてシードを入力 → Matching terms / Related terms / Search suggestions → エクスポート。Semrush → Keyword Magic Tool → データベースを日本にしてシードを入力 → Export（XLSX / CSV）。Google 広告のアカウントを持っていれば、Google キーワードプランナー →「新しいキーワードを見つける」→ 結果をダウンロード | 必須（基準ツールを1つ） | 数値を推測しない（鉄則1）。ボリューム・難易度の列は `[要追加: {ツール名}のエクスポート]` とし、候補の一覧と定性の整理だけ先に作る。代表表記と優先順位は、Google トレンドの比較（次の行）と CV への近さで暫定で決める |
| 検索需要の相対比較（表記ゆれ・候補同士）、季節性、急上昇している関連キーワード | Google トレンド（https://trends.google.co.jp/trends）→「調べる」でキーワードを入力し、比べたい語を同じグラフに追加 → 地域を日本、期間を設定（季節性は過去5年、最近の変化は過去12か月）→ グラフ右上の「ダウンロード」→ CSV。関連キーワード（上位 / 注目）は、表をダウンロードするかコピーして渡してもらう | 推奨（無料。有料ツールがないときは、代表表記と優先順位を決める主な材料） | 季節性と関心度は「未確認」と書く |
| 自サイトの規模（参照ドメイン数、インデックス登録済みページ数、月間の自然検索クリック数） | 参照ドメイン数: Ahrefs → Site Explorer → Referring domains、Semrush → Backlinks（旧 Backlink Analytics）→ Referring Domains、または Majestic。インデックス登録済みページ数: Search Console →「インデックス作成」→「ページ」。クリック数: Search Console →「検索パフォーマンス」→「検索結果」 | 必須（リストA / B / C の振り分けに使う） | ないものは `[要追加: ○○]` とし、振り分けを「暫定」にする。Search Console の「リンク」レポートはサンプルなので、参照ドメイン数の代わりにしない |
| 競合との差分 | Ahrefs → Competitive Analysis → Content Gap → 競合ドメインを入力 → エクスポート。Semrush → Keyword Gap → 自サイトと競合を入力 → Missing / Untapped タブ → Export | 任意 | site-brief の競合リストのサイトのカテゴリ構成を見て、定性の候補として追加する（数値は空欄） |
| サジェスト・関連語・質問 | ラッコキーワード → キーワードを入力 → サジェストキーワード / 関連キーワード / よくある質問検索 など → ダウンロードまたはコピー | 任意 | Ahrefs の Search suggestions、Semrush の Questions フィルタで代替する |
| 既存ページの一覧 | サイトマップ、または `scripts/audit.py` の出力 CSV（url, title） | 任意 | 「既存の対応URL」は GSC のページ別のファイルから埋められる範囲だけ埋め、残りは 04 の棚卸しで確認する |
| ランディングページ別の CV | GA4 →「レポート」→「エンゲージメント」→「ランディング ページ」→ キーイベント数を表示 →「このレポートを共有」→「ファイルをダウンロード」→ CSV | 任意 | CV への近さを定性で採点し、表の上に「CV 実績は未確認（暫定）」と書く |

## 3. 手順

1. シードトピックを事業から作る。
   - site-brief から、商材の一般名称、読者の悩み・課題、利用シーン、CV の種類、代替手段（競合サービスの種類）を抜き出す。
   - シードトピックは5〜10個。各トピックを、読者が検索窓に入れる数語（「商材 × 悩み × シーン」）に言い換える。社内用語・自社ブランド名だけにしない。
   - 既存サイトでは、Search Console のクエリ別のファイルから、表示回数が多いのに対応するページが弱いクエリをシードに加える。公開前・公開直後のサイトは Search Console にデータがないため、この作業は行わない（SKILL.md の「データがないときの動き方」）。
   - この段階ではボリュームで絞らない。

2. ツールで拡張し、全件エクスポートする。何を取るかは下の「ツールごとに取るもの」に従う。
   - シードごとに、キーワード・ボリューム・難易度・（あれば）現在の上位 URL を全件エクスポートする。数百〜数千行になってよい。
   - 取得条件（国: 日本、言語: 日本語、取得日）を記録する。条件が違うデータは同じ表で比べない。
   - Search Console の表示回数は自サイトが表示された回数であり、検索ボリュームではない。ボリューム列に入れない。
   - 主なシードは Google トレンドでも調べる。関連キーワード（注目）に出た語は候補に加え、季節性（過去5年の推移）があれば山の月をメモ列に書く。山の月は 04 の公開順と 10 の下落の判断に使う。関心度は相対値で検索回数ではないため、ボリューム列に入れない。

3. 基準ツールを1つ決め、数値をそろえる（鉄則1）。
   - ボリューム・難易度は基準ツールの値だけを使う。ツール間で値が違うのは普通のことで、平均・合算・つまみ食いをしない。
   - 難易度（Ahrefs の KD、Semrush の KD% など）は各ツール独自の指標で、ツール間に互換性はない。Google は、第三者ツールは Google 内部のランキングデータにアクセスできないと説明している（https://developers.google.com/search/docs/fundamentals/third-party-seo）。
   - 基準ツールで値が出ない語は、「0（ツールが0と表示）」「非表示（キーワードプランナーで表示対象外）」「未取得」を区別して書く。未取得は `[要追加: {ツール名}のボリューム]`。
   - 幅で表示された値（例: `1,000～1万`）は幅のまま記録する。中央値などの1つの数値に変換しない。
   - Google トレンドは基準ツールにしない（値が相対値のため）。有料ツールもキーワードプランナーもないときは、ボリューム列を `[要追加: 検索ボリューム（Ahrefs / Semrush などのエクスポート）]` のままにし、Google トレンドの比較と CV への近さで優先順位を暫定で決める。結論には「検索ボリューム未取得のため暫定」と書く。

4. 候補を整理する。
   - 事業と無関係な語（同名の別物、提供していない地域・商材、読者層が違う語）は、行を消さずに「除外したキーワード」の表へ移し、除外した理由を1語につき1行で書く。後で判断を見直せるようにするため。
   - 競合のブランド名を含む語は別グループにする。比較記事で扱うかどうかは表現上の制約（site-brief）を確認してから決める。
   - 表記ゆれは下の「表記ゆれの判断ルール」でグループ化する。

5. 検索意図とファネル段階を付ける。
   - 下の「検索意図の分類」で、主意図を1つ（必要なら副意図を1つ）と、ファネル段階（上・中・下）を付ける。
   - 意図があいまいな語には「意図あいまい」のフラグを立て、検索結果で何を見れば判断できるかをメモ列に書く（例: 情報収集に見えて商品ページが並ぶ、比較に見えてガイド記事が並ぶ）。最終的な判断は実際の検索結果で行う（手順8、05）。
   - 語の形だけでは確定しない。検索結果を見るまでは「（仮）」と書く。
   - 指名クエリ（自社名・自社サービス名）は、Search Console の検索パフォーマンス レポート（検索結果）にある「ブランド / 非ブランド」のクエリフィルタで分けられる。ただし URL のパスやサブドメイン単位のプロパティでは使えず、クエリと表示回数が十分なサイトに限られる。使えない場合は正規表現フィルタ（例 `{ブランド名}|{ブランド名の別表記}`）で分ける。

6. CV への近さ（1-5）を採点する（鉄則2）。基準は下の「CV への近さの採点基準」。
   - site-brief の CV ごとに採点し、どの CV で採点したかをメモ列に書く。CV が複数あるときは、最も近い CV の点を採る。
   - ボリュームが大きくても 1〜2点の語は後回しにする。ボリュームが小さくても 5点の語は優先候補に残す。
   - GA4 のランディングページ別キーイベントがあれば、既存ページの実績で採点を補正する。なければ「暫定」と明記する。
   - この点数は [00-principles.md](00-principles.md) の影響度（CV への近さ × 流入の規模）の材料になる。

7. 自サイトの規模を基準に、リストA / B / C に分ける。
   - 基準にする実データ: 参照ドメイン数、インデックス登録済みのページ数、月間の自然検索クリック数。ないものは `[要追加: ○○]` とし、振り分けを暫定にする。
   - 難易度スコアは粗い指標である。同じ値でも、参照ドメインが多いサイトには易しく、少ないサイトには届かないことがある。固定の閾値を置かず、自サイトがすでに上位にいる語の難易度と比べて判断する。新規サイトなど上位にいる語がなければ、上位ページのドメインと自サイトの参照ドメイン数の差（同じツールの値）で判断し、振り分けを暫定にする。上位の顔ぶれ（公的機関・大手・専門機関ばかりか）、一次情報を出せるか（site-brief の一次情報の源泉）、専門家の監修が要るテーマかも見る。
   - リストA「すぐ狙える」: 自サイトの規模で届く難易度で、作れる・既にあるページと意図が合い、ファネルの中〜下にある語。
   - リストB「専門性を築く」: トピックの深さを作り、被リンクを集める情報系の語。CV への近さは低くてよい。
   - リストC「後回し」: 少なくとも6か月は手を付けない語。理由を1行ずつ書く（例: 上位が公的機関と大手だけ、参照ドメイン数の差が大きい、一次情報を出せない）。初期に最も時間を浪費しやすいのがこの語群で、見直す時期も書いておく。
   - リストA・B の語には、上位で評価されていそうなページの種類（ガイド、一覧、比較、ツール、商品ページ、カテゴリページ、LP）を付ける。
   - 既に掲載順位8〜20位にいる語は、新規ページではなく既存ページの改善候補として [10-gsc-growth.md](10-gsc-growth.md) に回す。

8. リストA の上位10語（CV への近さの高い順、同点ならボリューム順）を実際に検索して確かめる。
   - 見る点: 上位が大手ブランドばかりか、掲示板・Q&A サイト（Yahoo!知恵袋など）が出るか、AI による概要が出るか、上位ページが古い・薄い・質が低いか。
   - 古く質の低いページが上位にあれば参入の余地がある。上位が大手ばかりで答えも十分なら、リストB か C に移し、理由を書く。
   - 「意図あいまい」の語は、上位ページの種類を見てここで意図を確定する。
   - 取得の方法と注意は 05 の手順2 に従う（シークレットウィンドウの結果を貼ってもらう。Web 検索ツールの結果は参考値）。

9. 04 へ渡す。
   - 出力フォーマットの表（リストA・B とリストC は別の表）と、SERP の重なりを確認したい表記ゆれグループの一覧を渡す。
   - キーワードごとにページを割り当てない。1キーワード1ページの発想は、同じ意図のページの量産（鉄則7違反）につながる。

### ツールごとに取るもの

| ツール | 画面 | エクスポートするもの | 注意 |
|---|---|---|---|
| Ahrefs | Keywords Explorer → Matching terms / Related terms / Search suggestions | キーワード、Volume、KD、SERP の上位 URL（必要なら） | 国の設定を日本にする。下の注記を参照 |
| Ahrefs | Competitive Analysis → Content Gap | 競合が上位で自サイトが入っていない語 | 競合は site-brief の競合リストから選ぶ。ドメインが大きすぎる総合サイトを入れると無関係な語が大量に出る |
| Semrush | Keyword Magic Tool | キーワード、Intent、Volume、KD%、SERP Features | 一致の範囲（Broad / Phrase / Exact / Related）と Questions フィルタを使い分ける。Intent 列は Informational / Navigational / Commercial / Transactional の4分類 |
| Semrush | Keyword Gap | Missing（入力した競合すべてが上位にいて、自サイトは入っていない語）、Untapped（競合のどれかが上位にいて、自サイトは入っていない語） | Organic を選ぶ。Paid・PLA は広告のデータ |
| Ahrefs / Semrush | Site Explorer → Referring domains / Backlinks → Referring Domains | 自サイトと競合の参照ドメイン数 | リストA / B / C の基準に使う。ツールごとに値が違うので、自サイトと競合は同じツールの値で比べる |
| Google トレンド（無料） | 「調べる」→ 比べる語を同じグラフに追加 → 地域・期間・カテゴリ・検索の種類（ウェブ検索、YouTube 検索など）を設定 | 関心度の推移（CSV）、地域別の関心度、関連キーワード（上位 / 注目） | 相対値で、検索回数ではない。比べる語は同じグラフに入れる（下の注記） |
| Google キーワードプランナー | 「新しいキーワードを見つける」（キーワードから / ウェブサイトから）、「検索のボリュームと予測のデータを確認する」（手持ちの一覧を確認） | キーワード候補、月間平均検索ボリューム、月別の検索数 | 検索広告を計画するためのツールで、Google 広告のアカウントが要る。類似パターンを含む平均値。幅で表示されることがある（下の注記） |
| ラッコキーワード | サジェストキーワード（Google・YouTube・Amazon・楽天・Bing など）、関連キーワード、潜在的な検索キーワード/質問（LSI/PAA）、よくある質問検索、同時ランクインキーワード | サジェスト、関連語、質問形の語 | 取れる項目・件数・出力の形式は、機能と契約状況で変わる。使う前に公式サイトで確認する |
| Search Console | 「検索パフォーマンス」→「検索結果」→「クエリ」タブ | 既に表示されているクエリ、表示回数、掲載順位 | UI のエクスポートは最大1,000行。匿名化されたクエリは表に出ないので、クエリ別の合計はグラフの合計より小さい。大規模サイトは API か一括データエクスポートを使う |

- Ahrefs の語の種類: Matching terms はシードの語を含む語（Terms match は語順を問わず、Phrase match は入力した語順どおり）。Related terms は、シードで上位のページが同時に順位を得ている語（Also rank for）と、上位ページがよく言及する語（Also talk about）で、シードを含む語も入る。Search suggestions は Google のオートコンプリートから取った語。
- Google トレンド: 値は相対値（関心度）で、検索回数ではない。対象の地域と期間の検索全体に占める割合を、最も多い時点を100として0〜100に調整している。検索の少ない語は0と表示される。同じユーザーが短時間に繰り返した検索は除かれ、プライバシー保護のための小さなノイズが加えられている（Google トレンド ヘルプ「Google トレンドのデータに関するよくある質問」。2026-09-26 に確認）。
  - 別々に表示したグラフの値は尺度が違うため比べられない。比べたい語は同じグラフに入れる（一度に比べられるのは、新しい「調べる」で最大8グループ、従来版で最大5グループ）。
  - 検索語句は入力した表記どおりに集計され、表記ゆれ・類義語・単数形と複数形の違いは含まれない。そのため表記ゆれ同士を同じグラフで比べると、どの表記が多く検索されているかがわかる。「トピック」は表記や言語をまたいでまとめて集計するので、表記ゆれの比較には使わない。
  - 関連キーワードの「上位」は、調べた語と同じ検索セッションで最も多く検索された語。「注目」は前の期間より大きく増えた語で、増加率が5,000%を超えると「急激増加」と表示される。注目の語は新しいテーマの候補として 04 に渡し、ボリュームは基準ツールで確かめる。
  - 新しい「調べる」では、Gemini による語の提案などが表示されることがある。Google はこれを試験運用中の機能とし、不正確な情報を表示することがあると説明している。提案された語は、事業と関係があるかを確かめてから使う。
  - 関心度とキーワードプランナーの検索ボリュームは別のデータで、換算できない。同じ列に混ぜない。公開する資料で引用するときは「データソース: Google トレンド（https://www.google.com/trends）」と書く。
- キーワードプランナー: Google 広告の検索キャンペーンのキーワードを調べるためのツールで、使うには Google 広告のアカウント設定（支払い情報の入力を含む）が必要（Google 広告ヘルプ「キーワード プランナーを使う」。2026-09-26 に確認）。広告を運用していないユーザーに、SEO のためだけに広告アカウントを作るよう求めず、Google トレンドとほかのツールで進める。月間平均検索ボリュームは、キーワードとその類似パターンが検索された回数の平均（既定は12か月）で、マッチタイプにかかわらず完全一致の統計が表示される。検索ボリュームがごく少ない語や、デリケートなトピックとされる語は表示されない。値が `1,000～1万` のような幅で表示されることがあり、広告の費用が少ない・出稿していないアカウントで幅表示になると広く報告されている（公式の条件の記載はない。2026年9月時点）。幅表示のデータを基準ツールにする場合は、列名を「ボリューム（幅）［キーワードプランナー］」とし、幅同士で比べる。
- Search Console Insights の「クエリグループ」は、表記ゆれを含む似たクエリを AI でまとめて表示する。クエリ数が多いプロパティに限られ、グループは時間とともに変わることがある。表記ゆれの当たりを付ける補助として使い、グループ分けの根拠にはしない。

### 表記ゆれの判断ルール

| 種類 | 例 | 扱い |
|---|---|---|
| ひらがな / カタカナ / 漢字 | めがね / メガネ / 眼鏡 | 同じグループに入れる。同じページで狙うかは 04 で SERP の重なりを見て決める |
| 送り仮名 | 申し込み / 申込み / 申込 | 同上 |
| 全角 / 半角 | ５０代 / 50代、ｉＰｈｏｎｅ / iPhone | 同上。ページ内の表記は voice-guide の表記ルールに合わせる |
| スペースの有無 | 転職 エージェント / 転職エージェント | 同上 |
| 略語・通称 | スマホ / スマートフォン | 同上。略語が別の意味を持つ場合は分ける |
| 長音の有無 | サーバー / サーバ | 同上 |
| 語順 | 東京 税理士 / 税理士 東京 | 同上 |
| 複合語と分かち書き | {商材名}保険 / {商材名} 保険 | 同上 |
| 同じ表記で意味が違う | {同音異義語}、{同名の別商品} | 表記ゆれではない。別の行にして意図を分けて書く |

- 代表表記は、基準ツールでボリュームが最大の表記にする。基準ツールがないときは、Google トレンドで表記ゆれ同士を同じグラフに入れて比べ（「トピック」ではなく検索語句で）、関心度が最も高い表記にする。同程度なら voice-guide の表記ルールに合わせる。
- 表記ゆれ同士のボリュームを足し合わせない。キーワードプランナーの値は類似パターンを含み、ほかのツールも表記ゆれをまとめて集計していることがあり、足すと二重に数える。
- まとめる最終判断は SERP で行う。上位10件の URL がよく重なれば同じページで狙い、本文で両方の表記を自然に使う。重ならなければ、読者の意図が違うとみなして別の行で 04 に渡す。
- Search Console のクエリは表記ごとに別行になる。グループの合計を見たいときは、正規表現フィルタ（例 `(めがね|メガネ|眼鏡)`）で絞る。

### 検索意図の分類

| 検索意図 | 読者の状態 | 語の手がかり | ファネル | 向いているページの種類 |
|---|---|---|---|---|
| 情報収集 | 知りたい、理解したい、やり方を知りたい | とは、意味、原因、違い、方法、手順、書き方、テンプレート | 上 | 解説記事、手順記事、用語集、ツール、テンプレート |
| 比較検討 | 選択肢を比べて選びたい | おすすめ、比較、ランキング、口コミ、料金、価格、{A} {B} | 中 | 比較記事、カテゴリページ、事例 |
| 取引 | 買いたい、申し込みたい、依頼したい | 購入、通販、申し込み、見積もり、予約、{地域} {業種} | 下 | 商品・サービスページ、LP、申込ページ |
| 指名 | 特定のブランド・サイト・ページに行きたい | 自社名、サービス名、ログイン、公式 | 語による（自社名の単独検索は下、競合名との比較は中） | トップページ、サービスページ、ログインページ |

- 分類は上の4つに統一する。Know / Do / Go / Buy など別の分類を使うチームは、対応を出力の「前提」に書き、1つの表で混ぜない。
- Semrush の Intent 列を使う場合は出典を明記し、Informational → 情報収集、Commercial → 比較検討、Transactional → 取引、Navigational → 指名 と読み替えた対応を表の上に書く。
- ファネル段階は読者の検討の段階、CV への近さは自社の商材で応えられるかの評価で、別の軸である。両方を付ける。
- Yahoo! JAPAN は Google の検索技術を使っている（運営会社 LINEヤフーの有価証券報告書、2026年6月提出。Google との契約は2027年3月31日まで）。ただし LINEヤフーは Google の検索結果を表示するかを自分で決められ、独自の機能も開発できるため、検索結果の画面が Google と同じとは限らない。キーワード調査は Google 基準のデータで行い、Yahoo! JAPAN 経由の流入（GA4 の参照元で確認）が多いサイトは 05 で Yahoo! JAPAN の検索結果も確認する。
- 日本語の検索結果では、Q&A サイト（Yahoo!知恵袋など）やフォーラムが上位に出る語がある。個別の状況や体験談を知りたい意図の手がかりになるので、手順8で確認する。

## 6. よくある失敗

- ボリュームや難易度を推測で書く: ツールの出力がない値は `[要追加: ○○]` にし、どのツールから何をエクスポートするかを伝える（鉄則1）。
- 複数ツールの数値を混ぜる、幅表示を1つの数値に置き換える: 基準ツールを1つ決め、列名に出典を書く。幅で表示された値は幅のまま比べる。
- 表記ゆれのボリュームを合算する: ツール側で類似パターンがまとめて集計されていることがあり、二重に数える。代表表記の値だけを使う。
- ボリュームを追って意図を無視する: 流入が増えても CV が増えない。検索意図・ファネル段階・CV への近さを先に見る（鉄則2）。
- Search Console の表示回数を検索ボリュームとして扱う: 表示回数は自サイトが表示された回数で、順位によって大きく変わる。ボリューム列には入れない。
- Google トレンドの関心度を検索回数として扱う: 0〜100の相対値で、比べる語・期間・地域が変わると尺度も変わる。ボリューム列には入れず、同じグラフに入れた語同士で比べる。
- 難易度スコアだけで狙えるかを決める: 同じ難易度でも自サイトの規模で結果が変わる。参照ドメイン数・インデックス登録済みページ数・月間クリック数の実データと照らしてリストに分ける。
- 初期からリストC の語に時間を使う: 大手や公的機関が占める語は、少なくとも6か月は手を付けない。理由と見直す時期を書いて保留する。
- 語の見た目だけで検索意図を確定する: あいまいな語にはフラグを立て、検索結果で上位ページの種類を見てから確定する。
- 無関係な語を行ごと消す: 除外の理由を1行ずつ残しておくと、後で判断を見直せる。
- キーワードごとにページを割り当てる: 割り当ては 04 で SERP の重なりを見て行う（鉄則7）。
