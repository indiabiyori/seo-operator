# 08 内部リンク

孤立ページ・クリック深度・ピラーとクラスターの相互リンク・アンカーテキストを点検し、「どのページのどこに、どの語句でリンクを足すか」を表で提案するための手順。

## 1. 目的

- CV に近いページと、順位8〜20位のページに、関連するページからリンクを集める。Google がページを見つけて内容を理解する手がかりを増やし、読者を CV への導線に乗せる（鉄則2）。
- サイトマップに載せているのに内部リンクがないページ（孤立ページ）と、トップページから遠すぎるページをなくす。
- 成果物は、リンク元・リンク先・アンカーテキスト・リンク元に入れる文まで決めた内部リンク追加の表。サイト構造そのものの設計は [04-topical-map.md](04-topical-map.md)、title や見出しの修正は [07-on-page.md](07-on-page.md) で扱う。

## 2. 必要な入力データ

| データ | 入手元（ツール → 画面 → 操作） | 必須/任意 | ないときの動き方 |
|---|---|---|---|
| 全ページの一覧（URL、title、主キーワード、1文の要約） | `scripts/audit.py` をサイトマップに対して実行し、出力 CSV の `url` / `status` / `title` / `h1_count` / `canonical_mismatch` / `robots_noindex` 列を使う。主キーワードはトピカルマップから、1文の要約は本文を読んで作るか CMS の抜粋を出してもらう | 必須 | サイトマップの URL を聞いて audit.py の実行を依頼する。ネットワークが制限された環境ではユーザーの PC で実行してもらう。サイトマップがなければ CMS の公開ページ一覧を CSV で出してもらう。主キーワードと要約が埋まらないページは `[要追加: 主キーワード]` とし、title から推定したものは「仮」と書く |
| 内部リンク（Search Console） | Search Console →「リンク」→「内部リンク」の「上位のリンクされているページ」→「詳細」→ 表をダウンロード（最大1,000行のサンプル。一括エクスポートはない）。行を選ぶとそのページへのリンク元が見られる | 必須（Screaming Frog のデータがあれば任意） | どちらもなければ孤立ページの判定はできない。`[要追加: 内部リンクのデータ（GSC の表または Screaming Frog の All Inlinks）]` を残し、トピカルマップに基づく相互リンクの設計だけ先に進める |
| 内部リンクの全件 | Screaming Frog →「Configuration > Spider > Crawl」で「Crawl Linked XML Sitemaps」を有効にしてクロール → Bulk Export → Links → All Inlinks。深度は Internal タブの Crawl Depth 列。無料版は1回500 URL までで、クロール設定を変えられないため、孤立ページの検出には有料ライセンスが要る | 任意 | GSC のデータだけで進め、孤立ページは「候補」と明記する。クリック深度は算出しない |
| トピカルマップ | [04-topical-map.md](04-topical-map.md) の成果物（ピラー・クラスター・URL の対応表） | 任意（ピラーとクラスターの相互リンクを提案するときは必須） | URL と title からクラスターの仮分類を作り、「仮分類」と明記する。04 の実施を提案する |
| 順位8〜20位のクエリとページ | `scripts/striking_distance.py` の出力（手順は [10-gsc-growth.md](10-gsc-growth.md)） | 任意（リンク先の優先度を付けるときは必須） | リンク先の優先度は CV との距離だけで暫定的に付け、根拠データ欄に `[要追加: striking_distance.py の出力]` と書く |
| ページ別のクリック数と CV | Search Console →「検索パフォーマンス」→「検索結果」→「ページ」タブのエクスポート（`ページ.csv` という名前のことが多い）、GA4 →「レポート」→「エンゲージメント」→「ランディング ページ」（キーイベント数） | 任意 | リンク元の候補を内部リンク数と関連性だけで選び、影響度を「暫定」と明記する |
| リンク元ページの本文 | ページの URL（Web 取得ツールが使える場合）または本文テキストを貼ってもらう | 任意（挿入位置と入れる文を提案するときは必須） | 挿入位置は「H2『{見出し}』の本文中」までにとどめ、入れる文は `[要追加: 本文]` とする |
| 変更ログ | [10-gsc-growth.md](10-gsc-growth.md) の変更ログ（反映日・判定予定日） | 任意（判定待ちのページを避けるときは必須） | 直近に変更したページを聞き、わからなければその旨を書いて進める |

## 3. 手順

1. 母集団をそろえる
   - audit.py の出力から、`status` が `200`、`h1_count` が空欄でない（HTML を解析できた）、`robots_noindex` が `False`、`canonical_mismatch` が `False` または空欄の URL を「リンクを受けるべきページ」とする。PDF など HTML でない行も `robots_noindex` と `canonical_mismatch` が入るので、`h1_count` の条件で外す。
   - `301>200` などリダイレクトするURL、404、noindex、canonical が別 URL のページは、リンク先として提案しない。既存リンクがこれらを指していれば、最終 URL への張り替えを提案し、原因の調査は [02-technical-audit.md](02-technical-audit.md) に回す。
   - 照合の前に URL を正規化する。スキームとホストの小文字化、`http` / `https` と `www` の有無の統一、末尾スラッシュをサイトの正規形に合わせる、フラグメントを除く。日本語 URL はツールによってパーセントエンコードされた形と日本語のままの形が混在するため、デコードした形にそろえてから突き合わせる。
   - audit.csv の文字列の列（`url`・`redirect_to`・`title`・`desc`・`canonical`）は、先頭が `=` `+` `-` `@`・タブ・CR のセルに `'` が付く（CSV インジェクション対策。`--no-sanitize` で無効）。URL は通常 `http` で始まるので影響しないが、title で突き合わせるときは先頭の `'` を除く。
   - audit.py は内部リンクを数えない。リンクの有無と本数は、必ず Search Console か Screaming Frog のデータで判断する。

2. 孤立ページを見つける
   - 定義: サイトマップにある（インデックスさせたい）のに、他のページからの内部リンクがないページ。
   - Screaming Frog（有料ライセンス）がある場合: 「Crawl Linked XML Sitemaps」を有効にしてクロールし、「Crawl Analysis > Start」を実行したうえで、Sitemaps タブの「Orphan URLs」フィルタを見る。
   - All Inlinks から判定する場合: Type が Hyperlink の行だけを残し、リンク元とリンク先が同じ行（自己参照）を除いてから、リンク先に一度も出てこない URL を探す。All Inlinks には画像・canonical・hreflang などへのリンクも入るため、絞らないと自己参照の canonical があるだけで「リンクあり」と誤判定する。
   - Search Console だけの場合: 内部リンクの表に出てこない URL を「孤立ページの候補」とする。このレポートは全リンクではなくサンプルで、表は1,000行まで、インデックスされていないページは省かれることがある。1,000ページを超えるサイトでは GSC だけで孤立と断定しない。候補のうち数件を実際のページで確認してから結論を出す。
   - 本文からのリンクがなく、ナビゲーションやフッターからしかリンクされていないページ（All Inlinks の Link Position が本文以外だけ）は「準孤立」として同じ表に載せる。
   - 見つけた孤立ページの扱いは次で分ける。
     - CV・流入・トピカルマップ上の役割があるページ → 同じクラスターのピラーと、関連の強いクラスター記事からリンクを足す。
     - 他のページと検索意図が重なるページ → リンクを足さず、統合と301リダイレクトを検討する（鉄則7、[04-topical-map.md](04-topical-map.md)）。
     - 役割がないページ → サイトマップから外す、noindex、削除のいずれかを [02-technical-audit.md](02-technical-audit.md) の手順で判断する。

3. クリック深度を確認する
   - Screaming Frog の Crawl Depth（開始ページからのクリック数。リダイレクトも1段と数える）を使う。
   - 目安: CV ページと主要なピラーは深度2以内、記事・商品ページは深度3以内。これは公式の基準ではなく実務上の目安で、サイトの規模に応じて調整する。
   - 深度4以上のページのうち、流入か CV があるページ、または striking_distance.py に出てくるページから対処する。
   - 対処の手段: カテゴリやハブページからのリンク、ピラーからのリンク、ページネーションの見直し（2ページ目以降にしか出ない記事をなくす）、関連記事モジュール、パンくずリスト。

4. ピラーとクラスターを相互にリンクする（トピカルマップに沿って）
   - すべてのクラスターは、自分のピラーにリンクする（本文の文脈の中に1本以上）。
   - すべてのピラーは、自分のクラスターすべてにリンクする（目次や一覧でよい）。
   - ピラーをまたいで関連するクラスター同士をつなぐ。読者の次の疑問に答える組み合わせだけにし、全記事の総当たりにしない。同じピラーの中のクラスター同士も同じ基準で選ぶ。
   - 同じ検索意図のページが2つ見つかったら、リンクの張り方で調整しようとせず、統合を優先する（鉄則7）。

5. 流入やリンクが多いページから順位8〜20位のページへリンクを足す
   - リンク先の候補: striking_distance.py の出力のうち、クエリに対応するページ（特定の方法は [10-gsc-growth.md](10-gsc-growth.md) の手順3）。CV ページか、CV への導線上にあるページを先にする。
   - リンク元の候補: リンク先と同じトピックで、次のいずれかに当てはまるページ。（a）Search Console のクリック数が多い、（b）外部リンクを多く受けている（「リンク」→「外部リンク」の「上位のリンクされているページ」）、（c）内部リンクを多く受けている。トピックが違うページからは張らない。
   - すでに流入があるサイトで2ページ目（11〜20位）で止まっているページには、関連性の高いページからの内部リンクを複数（目安5〜6本）向ける。本数は目安で、効くかどうかは測って判断する。
   - 同じリンク先への追加は1回の変更にまとめ、反映日を記録する（分類は `internal-link`）。判定待ちのページ（title の修正などを反映して判定日を過ぎていないページ）は、リンク先にもリンク元にもしない。効果測定の規則は [10-gsc-growth.md](10-gsc-growth.md) の手順7。
   - リンク元ページに同じリンク先へのリンクがすでにある場合は、本数を増やさずアンカーテキストの見直しだけを提案する。

6. アンカーテキストを決める
   - リンク先で何が得られるかが、アンカーだけを読んでもわかる語句にする。「こちら」「詳しくはこちら」「この記事」「ここをクリック」は使わない。Google の「リンクに関するベスト プラクティス」も、汎用的な語句を避けて具体的に書くよう案内している。
   - 同じリンク先に同じアンカーテキストを使うのは2回までにする。狙うクエリの完全一致だけで機械的にそろえず、文脈に合わせて言い回しを変える（この節の末尾の「アンカーテキストの例」）。
   - 短く、文の一部として自然に読める長さにする。リンクを連続して並べない。
   - 画像をリンクにする場合は、`alt` 属性にリンク先の内容を書く（アンカーテキストとして扱われる）。
   - 表記ゆれ（ひらがな・カタカナ・漢字、送り仮名）は文脈に合わせてよいが、リンク先の title と意味がずれないようにする。

7. パンくずリストを整える
   - すべてのページに、`<a href>` のリンクとして HTML のパンくずリストを置き、`BreadcrumbList` の構造化データを付ける。構造化データだけでリンクが画面にない状態にしない。
   - 階層は URL の構造ではなく、利用者がたどる典型的な経路に合わせる（Google のパンくずリストのドキュメントの推奨）。`ListItem` は2つ以上にする。
   - Google 検索でのパンくずリストの表示は、公式ドキュメント上パソコン版が対象になっている（2026年9月時点。実装前に最新版を確認する）。表示の有無にかかわらず、パンくずリストは内部リンクとして機能するので外さない。
   - 構造化データの書き方と検証は [07-on-page.md](07-on-page.md) に従う。

8. 関連記事モジュールを見直す
   - 同じクラスターの記事を出す（手動指定か、トピカルマップに対応したタグ）。「新着記事」だけでは古い記事にリンクが届かない。
   - HTML の初期レスポンスに `<a href>` で出力する。JavaScript で後から読み込む場合は、手順10の方法でレンダリング後の HTML にリンクがあるか確かめる。
   - 関連記事モジュールは本文中の文脈リンクの代わりにならない。手順5のリンクは本文に入れる。

9. ナビゲーションとフッターを絞る
   - グローバルナビには、CV ページ（料金・問い合わせ・資料請求など）と主要なピラー・カテゴリを置く。
   - フッターに「地域名×サービス名」のようなキーワードリンクを大量に並べない。利用者が実際に使うリンクに絞る。
   - Google の「リンクに関するベスト プラクティス」は、ページあたりの理想的なリンク数はないとしたうえで、多すぎると感じるならおそらく多すぎる、としている。メガメニューで全ページに数百本のリンクが出る構成は見直す。

10. JavaScript で生成するリンクを確認する
    - Google が推奨する形: `<a href="/path">`、`<a href="https://example.com/path">`。`href` があれば `onclick` などが併用されていてもよい（Google の「リンクに関するベスト プラクティス」の「リンクをクロールできるようにする」）。
    - Google が推奨しない形（Google が解析を試みることはあるが、確実にはたどれない）: `href` のない `<a onclick="...">`、`<span href="...">`、`<a href="javascript:...">`、`href` を出力しないルーター専用の属性だけのリンク。内部リンクは推奨される形にそろえる。
    - SPA では、ルーターのリンクコンポーネントが最終的に `<a href>` を出力しているかを確認する。
    - 「もっと見る」ボタンや無限スクロールで一覧を出すページは、`<a href="?page=2">` のようなクロールできるページ送りの URL も用意する。
    - 確認方法: Search Console の URL 検査 →「公開 URL をテスト」→「テスト済みのページを表示」で、レンダリング後の HTML に `<a href` があるかを見る。

11. 内部リンクに nofollow を付けない
    - 内部リンクに `rel="nofollow"` は不要。サイト内で評価の配分を調整する目的でも使わない。
    - クロールさせたくないページは robots.txt の `disallow`、インデックスさせたくないページは noindex で扱う（[02-technical-audit.md](02-technical-audit.md)）。Google の rel 属性のドキュメントも、自サイト内のリンクについては robots.txt の `disallow` を使うよう案内している。

12. 提案表を作り、優先度を付ける
    - 提案ごとに、リンク元URL、リンク先URL、アンカーテキスト案、リンク元ページの中で自然に入る文（挿入位置）を書く。
    - 影響度は、リンク先が CV にどれだけ近いかと、リンク先の表示回数（striking_distance.py の `impressions`）で決める。
    - 工数の目安: 本文へのリンク1本の追加は1、同じ作業を数十ページに行うなら2〜3、パンくずリストや関連記事モジュールなどテンプレートの改修は3〜5。
    - 優先度 = 影響度 ÷ 工数（採点基準は [00-principles.md](00-principles.md)）。同じ値なら影響度が高いほうを先にする（鉄則3）。
    - 優先度の上位20件は、その週のうちに入れる。入れたら反映日を変更ログに記録する（ひな形は [10-gsc-growth.md](10-gsc-growth.md)）。

### アンカーテキストの例（架空のページ）

| 避ける | 理由 | 使う |
|---|---|---|
| 詳しくはこちら | リンク先の内容がわからない | 法人向けプランの料金と契約条件 |
| この記事 | 同上 | 観葉植物の水やりの頻度（季節別） |
| 観葉植物 水やり（全ページで同じ語句） | 完全一致の機械的な連発。同じリンク先に同じアンカーは2回まで | 冬の水やりで根腐れを防ぐ方法 / 水やりの頻度の目安 |
| 観葉植物の水やり・肥料・植え替え・剪定の方法 | 長すぎて何のページかわからない | 観葉植物の植え替えの手順 |

```text
- 判定待ちのページ: {変更ログ または「なし」}
クラスター → 自分のピラー、ピラー → 自分のクラスターすべて、ピラーをまたいで関連するクラスター同士、の3種類のリンクを提案し、孤立ページも挙げてください。
提案ごとに、リンク元URL、リンク先URL、アンカーテキスト、リンク元ページの中で自然に入る文を書いてください。「こちら」は使わず、同じリンク先に同じアンカーは2回までにしてください。判定待ちのページはリンク元にもリンク先にもせず、「見送り」として分けてください。
優先度（影響度÷工数）の高い順に並べ、上位20件を「今週入れるもの」として分けてください。データにない数値は推測で埋めず、[要追加: ○○] で残してください。
```


```text
- 主なリンク先の title: {一覧}

リンク先の内容を推測で書き足さないでください。わからない場合は [要追加: リンク先の内容] としてください。
```

## 6. よくある失敗

- audit.py の出力だけで孤立ページを判定する: audit.py は内部リンクを数えない。リンクの有無は Search Console か Screaming Frog のデータで確かめる。
- Search Console のサンプルで孤立を断定する: 内部リンクの表は1,000行までのサンプルで、未インデックスのページは省かれることがある。GSC だけの判定は「候補」と書き、実ページで確認する。
- All Inlinks をリンクの種類で絞らずに使う: canonical・画像・hreflang の行が混ざり、孤立ページを見落とす。Type が Hyperlink の行だけを使い、自己参照を除く。
- URL を正規化せずに突き合わせる: 末尾スラッシュ、`www` の有無、日本語 URL のエンコードの違いで、リンクのあるページを孤立と誤判定する。照合の前に表記をそろえる。
- リダイレクト・noindex・HTML 以外の URL へリンクを足す: audit.py の `status`・`robots_noindex`・`h1_count` を確認し、HTML の正規ページにだけ張る。
- 同じリンク先に同じアンカーを何度も使う: 同じ語句の機械的な繰り返しは不自然に読める。同じリンク先に同じアンカーは2回までにし、文脈に合わせて言い回しを変える。
- 流入が多いという理由だけで無関係なページからリンクを張る: トピックが違うページからのリンクは読者の役に立たない。同じトピックのページだけをリンク元にする。
- JavaScript のボタンやクリックイベントでしか遷移できない: Google が確実にはたどれない。`<a href>` を出力し、URL 検査のレンダリング後の HTML で確認する。
- 内部リンクに nofollow を付けて評価を調整しようとする: 内部リンクに nofollow は不要。クロールやインデックスの制御は robots.txt と noindex で行う。
- 判定待ちのページにリンクを足す、または一度に大量に足して効果を測れなくする: 反映日と対象を記録し、判定日を過ぎるまで同じページに手を入れない。
