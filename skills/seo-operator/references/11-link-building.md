# 11 被リンクの獲得と監査

リンクを買ったり作ったりせず、他のサイトが参照したくなる理由を作って獲得するための施策、既存の被リンクの監査、アウトリーチの進め方をまとめた手順。

## 1. 目的

- 関連性の高いサイトからのリンクと言及を、スパムポリシーと法規制に触れない方法で増やす（鉄則6）。
- リンクを集めるページを、CV に近いページ・ピラーページ・順位8〜20位のページにつながる位置に置く。被リンクは CV に間接的にしか効かないため、内部リンク（[08-internal-linking.md](08-internal-linking.md)）で CV への導線につなぐ（鉄則2）。
- 既存の被リンクを把握し、否認が必要な状況かどうかを判断する。

## 2. 必要な入力データ

| データ | 入手元（ツール → 画面 → 操作） | 必須/任意 | ないときの動き方 |
|---|---|---|---|
| サイトの概要・CV・強み | `seo/site-brief.md` | 必須 | 先に初回セットアップ（[01-setup.md](01-setup.md)）を行う。ユーザーが待たずに進めることを選んだ場合は施策の一覧を示し、求められれば影響度を「（暫定）」として採点し、`[要追加: CVの定義]` を残す（基準は [00-principles.md](00-principles.md)） |
| 被リンク（Search Console） | Search Console →「リンク」→ 画面上部の「エクスポート」（外部リンク）→「最新のリンク」または「その他のサンプルリンク」（それぞれ最大100,000行）。「上位のリンク元サイト」「上位のリンク元テキスト」の表もダウンロードする（最大1,000行） | 監査では必須 | エクスポートを依頼する。届くまでは被リンクの件数・内訳に触れず、獲得施策の企画だけを進める |
| 被リンク・参照ドメイン（外部ツール） | Ahrefs / Semrush / Majestic で自ドメインの被リンク一覧と参照ドメイン一覧をエクスポートする | 任意 | Search Console のデータだけで進める。参照ドメイン数や DR などのツール独自の指標は書かず、`[要追加: 参照ドメイン一覧（ツール名）]` とする |
| 手動による対策の有無 | Search Console の「手動による対策」レポート（https://search.google.com/search-console/manual-actions） | 否認を検討するときは必須 | 確認してもらうまで否認の判断を保留する |
| 過去のリンク施策 | ユーザーへのヒアリング（リンクの購入、相互リンク、記事広告、SEO 業者への委託の有無と時期） | 否認を検討するときは必須 | 「不明」と記録し、否認は提案しない |
| 自社の資産の一覧 | 独自調査・統計・ツール・用語集・事例・図版など、公開済みまたは公開できるもの | 任意 | 元データがないものは企画だけを出し、数値やデータの欄は `[要追加: 元データ]` とする（鉄則5） |
| 実在する関係先 | 取引先、加盟している業界団体、所在地の自治体・商工会議所、協賛・登壇したイベント | 任意 | ユーザーに聞く。推測で関係先の候補を作らない |
| 競合の被リンク | Ahrefs / Semrush / Majestic で競合ドメインの参照ドメイン一覧をエクスポートする | 任意 | 競合との比較は行わず、自社の資産から施策を考える |
| トピカルマップ | [04-topical-map.md](04-topical-map.md) の成果物（ピラーとクラスター） | 任意（リンクされる資産を提案するときは必須） | site-brief の主要テーマから仮のピラーを置き、「仮」と明記する |

## 3. 手順

1. 依頼がスパムポリシーに触れないか判定する（鉄則6）
   - 依頼が下の「リンクスパムに当たる行為」に当てはまれば、該当する項目を示して実施しないと伝え、準拠した代替案を出す（下の「返答の型」）。
   - 「相互リンクをお願いしたい」「被リンクを何本か用意したい」「記事広告で通常のリンクをもらいたい」のような依頼も対象になる。

2. 現状の被リンクを監査する
   - Search Console のエクスポートをドメイン単位にまとめ、リンク元の種類を分ける: 関連する媒体の記事、取引先・団体、ディレクトリ・ランキングサイト、自動生成されたサイト、不明。
   - リンクを多く受けているページを確認する。リンクがトップページだけに集中していれば、手順3の資産で下層ページへのリンクを狙う。
   - 外部リンクを受けているのに 404 やリダイレクトチェーンになっている自サイトの URL は、内容の近いページへ 301 リダイレクトする（`scripts/audit.py` の `status` 列、[02-technical-audit.md](02-technical-audit.md)）。
   - 参照ドメイン数などの数値は、ツールのエクスポートにあるものだけを書く。Ahrefs の DR などはツール独自の指標で、Google の評価ではない。値を推測しない（鉄則1）。
   - 否認は、下の「否認を使う条件」に当てはまる場合だけ検討する。

3. リンクされる資産を用意する
   - 種類: 独自調査・アンケートの結果や独自データセット、公的統計を出典付きで整理し更新し続ける統計ページ、無料の計算ツール・診断ツール、決定版の用語集、テンプレート・チェックリスト、図版。
   - トピカルマップのピラーから、その分野の人が参照したくなる資産を5つ提案する。各案に次の4点を書く（出力フォーマットの「リンクされる資産の候補」）。
     - 何か（資産の中身と形式）
     - 誰がなぜリンクするか（記事を書く人・業界団体・教育機関など、リンクする側の理由）
     - 作るのにかかる期間（元データの収集から公開まで）
     - Claude Code で作れるか（計算ツール・テンプレート・用語集のページなど。作れない部分は何か）
   - 手元にある、または集められるデータを使う資産を優先する。データがない案は、集め方（アンケート、社内の記録の集計など）まで書いた場合だけ候補に残す。
   - テーマは、CV に関係するトピック（[04-topical-map.md](04-topical-map.md) のピラー）に近いものを選ぶ。リンクを受けた資産から CV ページへ内部リンクでつなげる。
   - 調査を出す場合は、調査方法・対象・期間・回答数を明記する。元データがなければ `[要追加: 調査データ]` とし、数値を作らない（鉄則5）。
   - 図版や統計の再利用条件（出典の明記とリンクを条件に転載可、など）をページに書いておく。

4. デジタルPR を行う
   - 目的は、メディアに記事として取り上げられ、記事中で言及・リンクされること。プレスリリース配信サービスに載ることで付くリンクそのものは、順位を上げる手段にならない。Google のリンクスパムの例には、他サイトに配信されるプレスリリース内の、キーワードを詰めたアンカーのリンクが含まれている。
   - 話題になる材料: 独自調査の結果、新サービス・新商品、地域での取り組み、専門家としてのコメント提供。
   - 送り先は、テーマを扱っている業界メディア・地域メディアの記者や編集部に絞り、個別に連絡する。
   - 健康食品・化粧品・医療機器などは薬機法、その他の業種別の表示規制がリリースの文面にも及ぶ。

5. リンクのないブランド名の言及にリンクを依頼する
   - Google で `"{ブランド名}" -site:example.jp` と検索し、カタカナ・英字・略称の表記ゆれでも検索する。言及しているがリンクしていないページを候補リストに入れる。
   - 相手はすでに自社を取り上げているので、面識のない相手への依頼より先に行う。
   - 読者にとって公式サイトへのリンクが役立つ場合（サービス名を紹介している記事など）だけ依頼する。依頼は短く丁寧に1回とし、アンカーテキストや rel 属性を指定しない（文例は下の「アウトリーチのメール文例」）。

6. リンク切れの代わりを提案する
   - 自社のテーマに近いページで、リンク先が 404 になっているリンクを探す（Ahrefs の Site Explorer →「Broken backlinks」で、テーマの近いサイトの 404 ページに向いたリンクを見る。または対象ページの発リンクを確認する）。
   - 自社のページが元のリンク先の内容を実際に置き換えられる場合だけ提案する。置き換えられなくても、リンク切れの報告だけは送ってよい。

7. 実在する関係先の掲載ページを確認する
   - 業界団体の会員一覧、取引先の導入事例・パートナー紹介、自治体・商工会議所の事業者紹介、出展した展示会の出展者一覧などに、正しい情報とリンクで掲載されているかを確認し、必要なら依頼する。
   - 相互リンクだけを目的としたパートナーページを作らない。契約や利用規約でリンクを条件にする場合は、相手が rel 属性を選べるようにする（スパムポリシーの項目）。

8. イベント・協賛を行う
   - 協賛・寄付の見返りとしてのリンクは対価のあるリンクなので、`rel="sponsored"` を付けてもらう。通常のリンクを求めない。
   - 協賛の価値は、参加者への認知と関係づくりにある。順位の手段として扱わない。

9. ローカルビジネスでは Google ビジネス プロフィールとサイテーションを整える
   - Google ビジネス プロフィールのカテゴリ・営業時間・住所・写真を正確にし、クチコミに返信する。Google の説明では、ローカル検索の順位は主に関連性・距離・知名度で決まり、知名度にはビジネスにリンクしているウェブサイトの数やクチコミの数なども使われる。
   - 店名・住所・電話番号の表記を、公式サイト・Google ビジネス プロフィール・ポータルサイト・地域サイトでそろえる（実務上の定石）。住所は「1丁目2番3号」と「1-2-3」、全角・半角の数字、ビル名の有無が揺れやすい。
   - クチコミを対価で集めたり、関係者に依頼して書かせたりしない（ステルスマーケティング規制の対象になりうる）。

10. 個別のアウトリーチを行う
    - 送る前に、リンクをもらいたい相手の記事そのものを読み、自社の資料との実際のつながりを見つける。つながりが見つからない相手には送らない。
    - 本文は数百字程度にする。相手の記事の具体的な一点に触れ、自社の資料が相手の読者にどう役立つかを1文で書き、URL を添える。
    - お世辞、決まり文句、圧力（期限、繰り返しの催促、見返りの示唆）を入れない。日本語のビジネスメールとして最低限の挨拶は残すが、定型の美辞麗句を重ねない。
    - 一斉送信しない。雑なメールを数百通送るより、相手ごとに書いた10通のほうがよい。候補を絞り、1通ずつ書く。
    - 金銭・商品・相互リンクを見返りにしない。アンカーテキストや rel 属性を指定しない。
    - 断られたら追わない。返信がない場合の再送は1回までにする。
    - 特定電子メール法: 営利目的の団体や営業を営む個人が、広告・宣伝の手段として送るメールは対象になり、原則として事前に同意を得た相手にしか送れない。例外として、自分のアドレスをインターネットで公表している相手には送れるが、アドレスと併せて広告宣伝メールを断る旨が公表されていれば送らない。対象になる場合は、送信者の氏名または名称、住所、受信拒否の通知ができる旨と通知先（メールアドレスまたは URL）、苦情・問い合わせの受付先（電話番号・メールアドレス・URL）を表示する（下の文例はこれを含めてある）。リンクの依頼が広告・宣伝に当たるかは内容によるので、判断に迷う場合は出力に `[要確認: 法務 特定電子メール法の対象か]` を残す。

11. 記録して効果を測る
    - 連絡した相手と結果を候補リストに記録する。獲得したら、リンク元 URL・リンク先・アンカー・rel 属性を獲得状況のログに書く。
    - 効果は、リンク先ページの表示回数・掲載順位（[10-gsc-growth.md](10-gsc-growth.md)）、GA4 の参照元からの流入と CV で見る。被リンクの効果は時間がかかるので、月単位で追う。

### リンクスパムに当たる行為（Google のスパムポリシー）

Google のスパムポリシーは、検索順位の操作を主な目的としてリンクを作る行為をリンクスパムとしている。例として挙げられているもの（要約。最新の内容は公式ドキュメントで確認する）:

出典: [Google ウェブ検索のスパムに関するポリシー「リンクスパム」](https://developers.google.com/search/docs/essentials/spam-policies?hl=ja#link-spam)（Google、CC BY 4.0。要約・改変）

- 順位を目的としたリンクの売買（金銭とリンク・リンク入りの投稿の交換、商品やサービスとリンクの交換、商品を送って紹介記事とリンクを書いてもらうことを含む）
- 過剰な相互リンク、相互リンクだけを目的としたパートナーページ
- 自動化されたプログラムやサービスによるリンク作成
- 利用規約や契約でリンクを義務づけ、相手が rel 属性を選べないようにすること
- 順位への評価を遮断しないテキスト広告・テキストリンク
- 対価を受けて掲載する記事広告・ネイティブ広告で評価を渡すリンク、他サイトに配信する記事・寄稿・プレスリリース内のキーワードを詰めたアンカーのリンク
- 質の低いディレクトリやブックマークサイトのリンク
- 複数のサイトに配布するウィジェットに埋め込んだ、キーワードを詰めたリンク・隠しリンク・質の低いリンク
- 複数のサイトのフッターやテンプレートに広く配置したリンク
- 掲示板のコメントや署名に入れた、キーワードを詰めたリンク
- リンクや順位のシグナルの操作を主な目的とした、価値の低いコンテンツの作成

広告や協賛のためのリンクの売買そのものは、`rel="nofollow"` か `rel="sponsored"` を付けていればポリシー違反にならない。

### スパムポリシーに触れる依頼への返答の型（鉄則6）

1. 結論: 「この依頼（{依頼内容}）は、Google のスパムポリシーのリンクスパム（{該当する項目}）に当たるおそれがあるため、実施を勧めない。」
2. 理由: スパムポリシーに違反したサイトは、順位が下がるか検索結果に表示されなくなるおそれがある。手動による対策を受けると、解除までの対応にも工数がかかる。
3. 代替案: 目的（{目的}）に対して、準拠した方法を影響度÷工数の順に示す。例: リンクの購入 → 独自調査の公開とデジタルPR、相互リンク集 → 実在する関係先の掲載ページの確認、記事広告 → `rel="sponsored"` と広告表示を付けたうえで認知の施策として実施。

### rel 属性の使い分け

| 値 | 使う場面 | 例 |
|---|---|---|
| `rel="sponsored"` | 広告・有料の掲載など、対価（金銭・商品提供など）のあるリンク | 記事広告、協賛・寄付の見返りのリンク、アフィリエイトリンク、商品提供を受けたレビュー内のリンク |
| `rel="ugc"` | コメントや掲示板など、ユーザーが投稿したコンテンツ内のリンク | ブログのコメント欄、Q&A、口コミ投稿 |
| `rel="nofollow"` | 上の2つが当てはまらず、リンク先とサイトを関連付けたくない場合 | 信頼を保証できないサイトへのリンク |

- 複数の値を組み合わせてよい（例: `rel="ugc nofollow"`）。
- 自サイト内のリンクには使わない（[08-internal-linking.md](08-internal-linking.md) の手順11）。

### 対価が絡む場合の表示（景品表示法のステルスマーケティング規制）

- 2023年10月1日から、事業者の表示であることが一般消費者にわかりにくい表示（いわゆるステルスマーケティング）は景品表示法の不当表示として規制されている。規制の対象は広告主である事業者で、依頼を受けたインフルエンサーなどの第三者ではない。
- 事業者が内容の決定に関与した投稿・記事は、第三者が書いても事業者の表示とされる。商品提供やレビュー依頼、記事広告では、「広告」「宣伝」「プロモーション」「PR」の表示や、「{社名}から商品の提供を受けて投稿している」といった文章で、広告であることがわかるようにしてもらう（消費者庁の運用基準の例）。
- 表示の義務（景品表示法）と、リンクの `rel="sponsored"`（Google のスパムポリシー）は別のルールなので、両方を満たす。
- 最新の運用基準と Q&A は消費者庁のページで確認する。

### 否認（disavow）を使う条件

- Google は、多くの場合どのリンクを信頼するかを自ら判断できるため、ほとんどのサイトでは否認ツールは不要としている。スパム的なサイトからの見覚えのないリンクは、基本的に放置してよい。
- 否認を検討するのは、次の両方に当てはまる場合: （1）スパム的・人為的・低品質なリンクが相当数ある、（2）それが手動による対策の原因になっている、またはなりそうである。典型例は、自社や委託した SEO 業者が過去に購入したリンクやリンクプログラムのリンクが残っている場合。
- 否認の前に、できるだけリンク元にリンクの削除を依頼する。
- 否認ツールはドメインプロパティに対応しておらず、URL プレフィックスのプロパティで使う。アップロードにはプロパティの所有者の権限が要る。
- ファイルは UTF-8 か 7 ビット ASCII の `.txt`、1行に1つの URL か `domain:example.com` の形式（`#` で始まる行はコメント）。最大100,000行・2MB、URL は2,048文字まで。サブパス（`example.com/en/` など）の単位では否認できない。
- リストはプロパティごとに1つで、新しくアップロードすると前のリストが置き換わる。追加するときは、前のリストに足したファイルをアップロードする。
- ツールが出す「有害度」などのスコアだけを根拠に一括で否認しない。Google のヘルプも、誤った使い方をすると Google 検索でのサイトのパフォーマンスを損なうおそれがあると警告している。

### アウトリーチのメール文例

どの文例も、末尾の署名欄に特定電子メール法の表示事項（送信者の名称、住所、苦情・問い合わせの受付先、受信拒否の通知ができる旨と通知先）を入れてある。広告・宣伝に当たらない連絡でも、そろえておけば判断を誤ったときの漏れを防げる。

共通の署名欄:

```text
{社名} {氏名}
住所: {住所}
お問い合わせ: {電話番号} / {メールアドレス} / {URL}
今後このようなご連絡が不要な場合は、次の宛先までお知らせください（受信拒否の連絡先: {メールアドレス または URL}）。
```

リンクのない言及へのお願い:

```text
件名: 「{相手の記事タイトル}」での弊社サービスのご紹介について

{媒体名} ご担当者様

{社名}の{氏名}です。{掲載日}の「{記事タイトル}」で、弊社の{サービス名}を取り上げていただきありがとうございます。{記事の具体的な箇所への一言}。
```

## 6. よくある失敗

- リンクの購入や相互リンクの依頼を「施策」として受ける: スパムポリシーのリンクスパムに当たる。該当する項目を示し、資産づくりとデジタルPRなどの代替案を出す。
- プレスリリースの配信でリンクが増えると考える: 配信サービス経由のリンクは順位の手段にならない。目的はメディアに取り上げられること。
- 商品提供や協賛のリンクに通常のリンクを求める: 対価のあるリンクは `rel="sponsored"`。ステマ規制の広告表示も別に必要になる。
- ツールの指標や参照ドメイン数を推測で書く: エクスポートにある値だけを使い、ないものは `[要追加: ○○]` とする。
- 有害度スコアを見て否認ファイルを一括で作る: 否認は手動による対策を受けたか、そのおそれがある場合に限る。誤った否認は検索でのパフォーマンスを損なうおそれがある。
- データのない独自調査を公開する: 調査方法と元データがない数値は作らない。`[要追加: 調査データ]` で止める。
- 同じ文面を一斉送信し、返信がない相手に何度も送る: 相手ごとに書き、断られたら追わない。再送は1回までにする。数を絞り、相手の記事を読んで書いた少数のメールにする。
- お世辞と決まり文句で長いメールを書く: 相手の記事の具体的な一点と、読者への利点の1文だけを書き、数百字程度に収める。
- 署名欄に受信拒否の連絡先や問い合わせ先がない: 特定電子メール法の対象になる場合は表示義務がある。文例の共通の署名欄を使う。
- リンクを得たページが CV につながっていない: 資産ページから CV ページへの内部リンクを設計する（[08-internal-linking.md](08-internal-linking.md)）。
