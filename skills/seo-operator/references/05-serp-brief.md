# 05 SERP 分析とコンテンツブリーフ

対象キーワードの検索結果（SERP）の上位を分析し、執筆者（人または Claude）がそのまま書き始められるコンテンツブリーフを作るための手順。執筆そのものは [06-writing-editing.md](06-writing-editing.md) で行う。

## 1. 目的

- 書く前に、上位ページが何で勝っていて何が足りないかを知る。上位ページと SERP 機能から、優勢な検索意図、求められているページの種類・形式・分量、必ず扱う論点を読み取る。
- 上位ページが扱っていない論点と、自サイトの一次情報で差を付ける箇所を決める（鉄則5）。
- ブリーフの8項目（下の「ブリーフの8項目」）に、title・出典・内部リンク・構造化データ・E-E-A-T・公開後の指標を加えて1枚にまとめ、CV への導線を明記する（鉄則2）。

## 2. 必要な入力データ

| データ | 入手元（ツール → 画面 → 操作） | 必須/任意 | ないときの動き方 |
|---|---|---|---|
| 対象キーワードとクラスター、担当 URL | [04-topical-map.md](04-topical-map.md) のトピカルマップ | 必須 | 04 がなければ、Search Console で対象クエリに既に表示されている自サイトの URL を確認してから進める（手順1。公開前・公開直後のサイトは既存ページの一覧だけで確認する）。確認できなければブリーフの冒頭に「重複未確認」と書く |
| 上位10件のタイトル・URL・SERP 機能 | ユーザーが Google をシークレットウィンドウで検索し、上位10件のタイトル・URL と、表示された SERP 機能を貼る。または Ahrefs → Keywords Explorer → SERP overview のエクスポート、Semrush → Keyword Overview → SERP Analysis のエクスポート | 必須 | Claude の Web 検索ツールで仮の分析をし、「参考値（ユーザーが見る日本語の Google の検索結果とは一致しない）」と明記する。順位や SERP 機能の有無の判断には使わない |
| 上位5件の見出し構成（h2 / h3）と本文 | ユーザーに見出しと本文を貼ってもらう。または Web ページ取得ツールで取得する（取得できたページだけ） | 必須（ブリーフ項目1〜3・5に使う） | タイトルと取得できた見出しから論点を推定し、「本文未確認」と明記する。字数の実態は空欄にする |
| 事業の前提（CV、想定読者、一次情報の源泉、表現上の制約） | 作業フォルダの `seo/site-brief.md` | 必須 | ブリーフは執筆の前段なので、先に初回セットアップ（[01-setup.md](01-setup.md)）を行う。ユーザーが先に進めることを選んだ場合だけ、一次情報の差し込み箇所と CTA を `[要追加: ○○]` にして、構成だけ作る |
| 文体・表記ルール | 作業フォルダの `seo/voice-guide.md` | 任意（06 では必須） | title 案の表記（全角・半角、表記ゆれの代表表記）は 03 の代表表記に合わせる |
| リライト対象ページの現状 | 対象 URL の本文、Search Console →「検索パフォーマンス」→「検索結果」→「+ フィルタを追加」→「ページ」で対象 URL に絞り込み →「クエリ」タブ →「エクスポート」 | リライト時は必須 | 本文だけで構成の差分を作り、「流入クエリ未確認」と書く |

## 3. 手順

1. 重複を確認する（鉄則7）。
   - 04 のマップで、同じ意図を担当する URL がないかを見る。あれば新規ブリーフではなく、そのページのリライト用ブリーフにする。
   - 既存サイトでは、Search Console の「クエリ」タブで対象クエリの行をクリックして絞り込み、「ページ」タブで既に表示されている自サイトの URL を確認する。2つ以上あれば、04 のカニバリゼーションの手順に戻る。

2. SERP を集める。
   - 方法A（推奨）: ユーザーに Google をシークレットウィンドウで検索してもらい、上位10件の「順位・タイトル・URL」と、表示された SERP 機能（下の表の項目）を貼ってもらう。デバイスは想定読者が主に使うもの（GA4 のデバイス別のセッション数で確認する）に合わせる。
   - 方法B: Ahrefs の SERP overview、Semrush の Keyword Overview → SERP Analysis をエクスポートしてもらう。ツールが取得した日時・条件の結果なので、取得日を記録する。
   - 方法C（参考）: Claude の Web 検索ツール。ユーザーが見る日本語の Google の検索結果（地域・端末・パーソナライズ）とは一致しないため、「参考値」と明記し、論点の洗い出しの補助にだけ使う。
   - 上位5件は開いて、見出し構成（h2 / h3）を写し、本文の字数と形式を記録する。AI による概要・動画・他の人はこちらも質問・掲示板や Q&A サイト・ショッピングが出ているかも記録する。
   - Google の検索結果を独自スクリプトで自動取得しない（[04-topical-map.md](04-topical-map.md) の手順2）。`scripts/audit.py` も SERP の取得には使わない。
   - 検索結果は時間・場所・デバイス・検索履歴によって変わる。1回の結果を絶対視せず、取得条件を記録する。

3. SERP を分析する。観点と判断ルールは下の「SERP 分析の観点」に従う。
   - 上位10件を1行ずつ「ページの種類・形式・切り口・主な論点」で分類してから、全体の傾向をまとめる。
   - 自サイトが作れるページの種類と、SERP で優勢な種類が違う場合（例: 上位が商品一覧なのに記事を作ろうとしている）は、ブリーフを作らずに 04 に戻してキーワードの担当を見直す。

4. 論点を決める（ブリーフ項目1〜3）。上位5件の見出しと本文を並べて数える。
   - 上位5件のすべて、または3件以上が扱う論点は「基本項目」にする。欠けると検索意図を満たせない。
   - 1〜2件だけが扱う論点は「切り口」の候補にし、想定読者に必要かで取捨する。
   - どこも扱っていない論点、扱いが浅い論点は「強み」の候補にする。ただし、読者の疑問として実在するか（他の人はこちらも質問、関連検索、Q&A サイトの質問、サジェスト）で裏付けを取る。
   - 上位ページの見出しを寄せ集めて構成を作らない。読者の疑問の順番で並べ直す。

5. 自サイトならではの切り口を決める（ブリーフ項目8、鉄則5）。
   - site-brief の「一次情報の源泉」（自社データ、支援事例、専門家、現場の写真、検証結果など）から、強みの論点を埋められるものを選ぶ。
   - AI には作れない一次体験・データ・事例を3つ選び、ユーザーに尋ねる（何を、誰から、どの形式で）。Claude は作らない。経験を示す近道は、その人にしか分からないもの（検証結果、スクリーンショット、失敗、顧客の数値）を入れることである。
   - 手元にない一次情報はブリーフに `[要追加: {何の情報を、誰から、どの形式で}]` として置く。例: `[要追加: 過去の支援事例のうち{条件}に当てはまる1件（業種・課題・結果。社名は伏せてよい）]`。
   - 一次情報を出せない語で、上位が一次情報を持つ専門サイトばかりなら、ブリーフの冒頭に「実現可能性: 低」と書き、03 のリストを見直す。

6. 形式と分量を決める（ブリーフ項目5）。
   - 上位の実態（多数派の形式、見出しの数、本文の字数の範囲）を記録し、形式は多数派に合わせる。外すなら理由を書く。
   - 字数は一般論や競合の平均を目標にしない。Google は、優先される文字数という設定は存在しないと説明している。上位の範囲を参考にしつつ、論点の数と各節で必要な深さから「{n} 節 × 各 {m} 字程度」のように見積もる。

7. ブリーフを書く。項目と書き方は下の「ブリーフの8項目」「そのほかの項目の書き方」と「5. 出力フォーマット」に従う。

### SERP 分析の観点

| 観点 | 見るもの | 判断ルール |
|---|---|---|
| 優勢な検索意図 | 上位10件のページの種類の多数派 | 目安として7件以上が同じ種類なら意図ははっきりしている。4〜6件で割れているなら意図が混在しており、主意図に合わせたうえで副意図は1節で扱うか、04 で別クラスターにする |
| ページの種類 | 記事、カテゴリページ、商品ページ、ツール・シミュレーター、動画、公式サイト、Q&A サイト・フォーラム | 自サイトが作れない種類が優勢なら、ブリーフを作らず 04 に戻す |
| 形式と分量 | 手順、比較、一覧（ランキング）、定義・解説、体験談、テンプレート。上位5件の見出しの数と字数 | 多数派の形式を基本にする。分量は範囲として記録し、平均を目標にしない |
| 切り口 | 対象読者（初心者 / 経験者、個人 / 法人）、時点（年度・最新）、地域、価格帯 | 上位と同じ切り口で勝てる根拠がなければ、site-brief のターゲットに合う切り口に絞る |
| 論点の分布 | 上位5件の見出し・本文、他の人はこちらも質問、関連検索、Q&A サイトの質問、サジェスト | 手順4の基準で、基本項目・切り口・強みに分ける |
| 情報の鮮度 | 上位ページの公開日・更新日、年号入りのタイトル | 更新日が新しいページが多いテーマは、公開後の更新計画（誰が・いつ）をブリーフに書く |

### SERP 機能ごとの読み取り方

| SERP 機能 | 意味すること | ブリーフへの反映 |
|---|---|---|
| AI による概要 | 質問に要約で答えられるクエリ。引用元のリンクが表示される | 引用されているサイトと論点を記録し、冒頭の直接の答え（ブリーフ項目7）を必ず書く。AI による概要のための特別なマークアップや専用ファイルは不要と Google は説明している。詳しくは [09-ai-search.md](09-ai-search.md) |
| 強調スニペット | 定義文・手順・表で短く答えられる問い | 対応する見出しの直後に、問いへの答えを1〜2文、または番号付きの手順・表で置く |
| 他の人はこちらも質問 | 読者が続けて持つ疑問 | 質問文と、ページ内のどこで答えるか（見出しと、その直後の文）をブリーフ項目4に書く |
| 動画 | 手順や使い方を映像で見たい意図 | 動画を埋め込めるか、動画ページを作るかを検討する。作れない場合は図や写真の手順を増やす |
| 画像 | 見た目・デザイン・完成形を確認したい意図 | オリジナルの画像（撮影・図解）を差し込む箇所を `[要追加: 画像]` で指定する |
| ショッピング（商品の一覧・価格） | 商品を探して比べたい取引意図 | 記事よりカテゴリページや商品ページが向いている。EC なら Merchant Center の情報と商品の構造化データを確認する（[07-on-page.md](07-on-page.md)） |
| ローカルパック（地図と店舗の一覧） | 近くの店舗・事業者を探す意図 | Google ビジネスプロフィールの整備が先。ページでは所在地・対応エリア・営業時間を明記する |
| ディスカッションとフォーラム、Q&A サイト（Yahoo!知恵袋など） | 個別の状況や体験談を知りたい意図 | 体験・事例・よくある状況別の答えを厚くする。体験や事例は `[要追加]` で一次情報を求める |

- Yahoo! JAPAN の検索結果は Google と同じとは限らない（[03-keyword-research.md](03-keyword-research.md) の「検索意図の分類」）。Yahoo! JAPAN からの流入が多いサイトは、Yahoo! JAPAN の検索結果も同じ方法で確認し、違いを分析欄に書く。

### ブリーフの8項目

| 項目 | 書くこと | 判断ルール |
|---|---|---|
| 1. 基本項目 | 上位5件のすべて、または3件以上が扱う内容 | 必ず入れる |
| 2. 切り口 | 1〜2件だけが扱う内容 | 想定読者に必要なものだけ採る |
| 3. 強み | どこも扱っていないが、検索者が知りたい内容 | 他の人はこちらも質問・関連検索・Q&A サイトの質問・サジェストで実在を確かめ、自サイトが答えられるものにする |
| 4. 他の人はこちらも質問 | 質問文と、ページ内で答える位置（見出し） | 本文で答える。FAQ の構造化データ（FAQPage）は使わない（下の「構造化データ」） |
| 5. 形式と分量 | 上位の実態（形式、見出しの数、字数の範囲）と、このページの形式・分量の見積もり | 一般論の字数や平均を目標にしない（手順6） |
| 6. H2 / H3 の構成 | 読者の疑問の順に並べた見出しと、各見出しが答える問い | 上位の見出しの寄せ集めにしない |
| 7. 冒頭の直接の答え | 主な検索への答えを、h1 の直後に置く2〜3文、100〜150字程度の、単独で引用できる完結した文 | 前後の文脈がなくても意味が通るように書く。前置き（「この記事では〜」）から始めない |
| 8. 一次情報（3つ） | AI には作れない一次体験・データ・事例を3つと、それぞれを誰に何の形式で尋ねるか | Claude は作らずにユーザーに尋ねる。届くまで `[要追加: ○○]` のまま残す（鉄則5） |

### そのほかの項目の書き方

- title 案: 全角30字前後を目安に5案出し、全角換算の文字数を併記する（数え方は [07-on-page.md](07-on-page.md) の「全角換算の数え方」）。表示はデバイスの幅で切られ、Google は h1 や og:title なども使ってタイトルリンクを決めるため、書いた title がそのまま出るとは限らない。代表キーワードと読者が得るものを前半に置き、title と h1 の主題をそろえる。
- meta description 案: 全角80〜120字前後で3案出し、文字数を併記する。Google はスニペットを主にページ本文から作り、meta description のほうがページを正確に表すと判断した場合に使う。検索意図への答えの要約と、ページで得られるもの（比較表、手順、事例など）を書く。キーワードを詰め込まない。
- h1: title とほぼ一致させる（完全に同じでなくてよい）。主題は必ずそろえる。
- 各節で必ず扱う事実と出典: 公的機関・法令・メーカーの公式情報など一次資料を優先し、URL を書く。出典のない数値・統計は書かない。確認できない事実は `[要追加: 出典]` にする。
- CV と CTA: site-brief の CV から、この記事が導く CV を1つ決める。CTA の文言と設置位置（本文の途中、末尾、比較表の直後など）を書く。CV への近さが低い記事（情報収集）は、いきなり問い合わせではなく、次の段階のページ（比較記事、事例、サービスページ）へのリンクを CTA にする。
- 内部リンク: 04 のマップから「張る先」（ピラー、CV ページ、関連クラスター）と「張られる元」（ピラー、関連記事）を URL とアンカーテキストの案付きで書く。詳細は [08-internal-linking.md](08-internal-linking.md)。
- 構造化データ: ページの種類に合うものを指定する。記事なら Article / BlogPosting（author、datePublished、dateModified）、階層があれば BreadcrumbList、EC の商品なら Product。FAQ のリッチリザルトは2026年5月7日以降 Google 検索に表示されていない。HowTo のリッチリザルトは2023年9月13日に廃止された（経緯は [07-on-page.md](07-on-page.md) の「リッチリザルトの提供状況」）。FAQ のマークアップを AI 検索対策として勧めない。FAQ の内容を本文に書くこと自体は、読者のためなら構わない。値は公開時の実データで埋め、わからないプロパティは JSON-LD に書かない（[07-on-page.md](07-on-page.md) の手順11）。
- E-E-A-T の要素: 著者名と著者のプロフィールページ（経歴・資格・実務経験）、監修者（健康・お金・法律など、読者の生活に大きく影響するテーマでは専門家の監修を検討する）、公開日と更新日（ページ上の目立つ位置に「公開日」「最終更新日」とラベルを付けて表示し、構造化データの日付と一致させる）、出典の一覧。実質的な変更がないのに日付だけ新しくしない。
- 表現上の制約: site-brief の制約欄から、景品表示法（広告であることの表示、ステルスマーケティング規制）、薬機法など業種ごとの表現規制で注意する点を書く。
- 公開後に見る指標: Search Console の検索パフォーマンス レポート（検索結果）を対象 URL で絞り込んだ表示回数・掲載順位・CTR、生成 AI パフォーマンス レポート（検索）の表示回数（AI による概要・AI モードでサイトのリンクが表示された回数。ページ・国・デバイス・日付別で、クエリとクリック数はない。表示回数が少ないサイトには出ない）、GA4 のキーイベント（CTA のクリック、CV）。
  - 起点は本番への公開日（リライトなら反映日、以下 D）。確認日は「D + 観察日数 + 遅延日数」以降にする（Search Console のデータは通常2〜3日遅れる）。観察日数は28日が基本で、D の31日後に確認する（窓は D+1〜D+28）。7日で見るのは、表示回数が十分に多いページで変化の兆しを早く見る場合だけ。新規ページは12週間（84日）後にも確認する。
  - リライトの判定は [10-gsc-growth.md](10-gsc-growth.md) の「手順7 効果を測る」に従う。反映前の同じ長さ・同じ曜日構成の期間と比べ、同じカテゴリで変更していないページ（対照）の同じ期間の増減と並べて、改善・変化なし・悪化・判定不能のどれかにする。判定不能なら分類を変えずに観察を延ばす。確認日まで、同じページ・同じクエリ群に別の変更を入れない。
  - リライトを検討する条件を書く。効果を予測で書かない。

## 4. そのまま使えるプロンプト

```text
キーワード「{キーワード}」の SERP を分析してください。以下は私が Google をシークレットウィンドウ（{スマートフォン / パソコン}、{YYYY-MM-DD}）で検索した上位10件と SERP 機能、上位5件の見出し構成です。
{順位 / タイトル / URL を10行、表示された SERP 機能（AI による概要の有無と引用元、強調スニペット、他の人はこちらも質問の質問文、動画、画像、ショッピング、ローカルパック、Q&A サイトなど）、上位5件の h2 / h3 と本文の字数}
- 上位10件をページの種類・形式・切り口で分類し、優勢な検索意図を判定する
- 上位5件の論点を、すべて（または3件以上）が扱う基本項目、1〜2件だけが扱う切り口、どこも扱わない強みの候補に分ける
- 上位の形式・見出しの数・字数の範囲を実態として記録する。平均を目標にしない
- 自サイト（seo/site-brief.md）が作れるページの種類と合わない場合は、ブリーフを作らずにその旨を書く
- 本文を確認していないページは「本文未確認」と明記し、推測で論点を補わない
```

## 6. よくある失敗

- Claude の Web 検索ツールの結果を Google の順位として扱う、検索結果をスクリプトで取得する: 検索エンジン・地域・端末が違うため一致せず、自動取得はスパムポリシーの「機械生成トラフィック」に当たる。ユーザーに貼ってもらうか、ツールのエクスポートを使う。
- 競合の平均文字数を目標にする: 優先される文字数という設定はない。上位の範囲は実態として記録し、分量は論点の数と深さから見積もる。
- 上位ページの見出しを寄せ集めて構成にする: どのページとも同じ内容になり、選ばれる理由がない。基本項目・切り口・強みに分け、読者の疑問の順に並べ直す。
- 冒頭で答えず、前置きから始める: 冒頭の直接の答え（2〜3文、100〜150字程度、単独で意味が通る文）をブリーフに書いておく。
- 体験談や事例を創作する、または尋ねずに `[要追加]` を並べるだけで渡す: AI には作れない一次体験・データ・事例を3つ選び、誰に何を尋ねるかまで書く（鉄則5）。
- 04 を確認せずに新規ブリーフを作る: 既存ページと同じ意図のページが増える。先に重複を確認し、あればリライトにする（鉄則7）。
- title・meta description の文字数を書かない、半角を全角と同じに数える: 全角換算の文字数を必ず併記する。表示はデバイスの幅で切られ、Google が書き換えることもある前提で、前半に要点を置く。
- FAQPage や HowTo でリッチリザルトや AI 検索での効果を見込む: どちらも現在 Google 検索でリッチリザルトとして表示されない。質問への答えは本文に書き、構造化データは表示中の機能だけを指定する。
- CTA が CV と対応していない: 情報収集の記事に問い合わせボタンだけを置くのではなく、次の段階のページへのリンクを用意する（鉄則2）。
- 内容を変えずに更新日だけ新しくする: Google は実質的な変更のない日付の変更を避けるよう求めている。更新したら何を変えたかを記録する。
