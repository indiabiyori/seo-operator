# 01 初回セットアップ（site-brief と voice-guide）

作業フォルダの `seo/site-brief.md` と `seo/voice-guide.md` を作成・更新する手順をまとめる。SKILL.md の「初回セットアップ」を詳しくしたもので、流れはそれと同じである。

## 1. 目的

- 施策の優先度（鉄則2・3）を決める前提（事業、CV、主要ページ、競合、制約）を1つのファイルにそろえる。
- 記事の文体・表記・禁止表現を voice-guide にまとめ、執筆とリライト（[06-writing-editing.md](06-writing-editing.md)）の基準にする。
- 使える一次情報の源泉を把握し、体験やデータを創作せずに済むようにする（鉄則5）。
- 業種ごとの法規制・表示ルールに該当するかを、ユーザー自身に確認してもらう。

## 2. 必要な入力データ

| データ | 入手元（ツール → 画面 → 操作） | 必須/任意 | ないときの動き方 |
|---|---|---|---|
| 事業内容・ビジネスモデル・CVの定義・ターゲット | ユーザーへの質問（下の質問リストの第1回） | 必須 | 答えがない欄は `[要追加: ○○]` で残す。CVの定義がないと優先度を確定できないことを伝える |
| GA4 のキーイベント名 | GA4 →「管理」→「データの表示」→「イベント」→ キーイベントとしてマークされたイベント名を確認（2024年3月に「コンバージョン」から改名。現在の「コンバージョン」は Google 広告の測定用の別の概念） | 必須（CVを計測している場合） | `[要追加: GA4のキーイベント名]` を残す。計測していなければ、計測の設定を施策候補として記録する |
| 主要ページ・競合リスト（狙う語で上位にいるサイト3〜5件）・法規制などの制約 | ユーザーへの質問（第2回） | 必須 | `[要追加: ○○]` を残す。法規制は該当の確認を依頼し、回答まで制約欄を埋めない |
| 最初に渡すデータ（最新の Search Console エクスポート、サイトマップの URL 一覧、既存のキーワード調査） | ユーザーから受け取る。Search Console →「検索パフォーマンス」→「検索結果」→「エクスポート」、サイトマップの URL、過去の調査ファイル | 任意（公開前のサイトは Search Console のデータなし） | ないものは site-brief の「手元のデータ」に `[要追加: ○○]` と書き、データが要る作業のたびに依頼する |
| 公開ページ（会社概要、主要サービスページ、料金ページ） | ユーザーから URL を受け取り、Web ページ取得ツールで読む。使えなければ本文を貼ってもらう | 任意（下書きに使う） | 質問だけで埋める（方法B） |
| よく読まれている記事 | Search Console →「検索パフォーマンス」→「検索結果」→「ページ」タブ → クリック数の降順 →「エクスポート」。または GA4 →「レポート」→「エンゲージメント」→「ランディング ページ」→「このレポートを共有」→「ファイルをダウンロード」→ CSV | 任意 | ユーザーに「読者の評価が高いと思う記事」を3〜5本挙げてもらう |
| 文体の見本になる記事3〜5本の本文 | 上の一覧から選び、URL か本文を受け取る | 任意（voice-guide の抽出に使う） | voice-guide を `[要追加: ○○]` のまま渡し、方法Aで記入してもらう |
| 利用できるツールと権限 | ユーザーへの質問（Search Console、GA4、キーワードツールなど） | 任意 | `[要追加: 利用できるツール]` を残し、データが要る作業のたびに確認する |

## 3. 手順

1. 既存ファイルを確認する。作業フォルダの `seo/site-brief.md` と `seo/voice-guide.md` を探す（ユーザーが別の保存場所を指定していればそこ）。
   - 両方ある: 読み込み、`最終更新日` を見る。6か月以上前なら見直しを提案する（手順9）。
   - 片方だけある: ないほうだけ作る。
   - 名前の違う既存資料（ペルソナ資料、表記ルール集など）がある: 捨てずに、テンプレートの欄へ移す下書きの材料にする。
2. ないファイルがあればユーザーにそう伝え、テンプレートをコピーする。スキルフォルダ内のテンプレートは編集しない（クラウドセッションや Cowork では読み取り専用のことがあり、サイト固有の情報をスキルに混ぜないため）。既存ファイルは上書きしない。
   ```bash
   mkdir -p seo
   cp -n <スキルのディレクトリ>/templates/site-brief.md seo/site-brief.md
   cp -n <スキルのディレクトリ>/templates/voice-guide.md seo/voice-guide.md
   ```
   - 作業フォルダが Git で管理されているなら、CVの単価など社外秘の値をコミットしてよいか確認する。
3. 記入の方法を選んでもらう。
   - A: ユーザーが自分で記入し、終わったら知らせてもらう。記入後に Claude が読み、空欄と矛盾を指摘する。
   - B: Claude が質問して埋める。公開サイトがあれば、先に公開ページから下書きを作り（手順5）、質問を減らす。
4. 方法Bでは、下の質問リストの順に聞く。
   - 1回の質問は5問以内。第1回と第2回（必須項目）が終わるまで第3回に進まない。
   - 回答を反映したら、書いた内容を要約して見せ、違いがないか確認してもらう。
   - 「わからない」「答えられない」は `[要追加: ○○]` のまま次へ進む。推測で埋めない。
   - 答えにくい値（CVの価値など）は、範囲や相対値（「CV A は CV B の約3倍」）でよいと伝える。
   - 公開ページで確認できることは質問せず、下書きで示して確認だけ求める。
5. 公開ページから下書きを作る（下の対応表）。
   - ページに書かれた事実は、出典 URL を添えて記入する。
   - ページから推測した内容（読者像、強み、競合など）は `[要確認: {推測した内容}（根拠: {URL}）]` と書き、最後にまとめて確認を依頼する。
   - CVの価値、KPI、社内の禁止事項、利用できるツールと権限、一次情報の源泉は推測しない。`[要追加: ○○]` のままにする。
   - `[要確認]` が残った値は、優先度の採点で暫定として扱う（[00-principles.md](00-principles.md)）。確認が取れたらマークを外す。
6. voice-guide を既存記事から抽出する（下の「voice-guide の抽出手順」）。記事がない新規サイトは方法Aか、第3回の後に文体の希望を質問する。
7. 業種別の法規制・表示ルールを確認してもらう（下の一覧）。Claude は法的な判断をしない。該当するか、社内の確認フロー（法務・監修者）があるかをユーザーに確かめ、site-brief の「制約」に書く。
8. 仕上げる。両ファイルの `最終更新日` と更新履歴を書き、残った `[要確認]` と `[要追加]` を一覧にして渡す（出力フォーマット）。CVの定義が埋まっていなければ、優先度は暫定になると伝える。
9. 更新のタイミングを案内する（下の「更新のタイミング」）。

### 依頼文の組み立て方（文脈を先に、質問を最後に）

セットアップ後の依頼では、最初の質問の前に次の文脈を渡す。
- site-brief: 何のサイトか、誰向けか、何を売るか、競合と何が違うか。
- voice-guide: 書き方、使う語、使わない語。
- 競合リスト: 狙う語の検索結果で上位にいるサイト3〜5件（site-brief の「検索上の競合」）。
- データ: 最新の Search Console エクスポート、サイトマップの URL 一覧、既存のキーワード調査（site-brief の「手元のデータ」）。

並べる順番は、変わりにくい文脈（site-brief、voice-guide、ページ一覧）→ データ → 今回の質問・依頼。質問を最後に置くと、文脈が同じ依頼では質問だけを差し替えて再利用できる。データにはファイル名と取得日を添える。

### 方法Bの質問リスト（1回5問以内）

質問文の例。依頼内容や既に分かっていることに合わせて削ってよい。

第1回（必須: 事業とCV）

1. どんな事業で、誰に何を提供し、どこで収益を得ていますか。
2. サイトで増やしたい成果（CV）は何ですか。問い合わせ・購入・資料請求などのうち、何をもって1件と数えますか。
3. その CV は GA4 のキーイベントとして計測していますか。していればイベント名を教えてください。
4. CV 1件の価値の目安を教えてください（平均単価や成約率など。社外に出せなければ相対値でかまいません）。
5. 主な読者はどんな人で、どんな場面・悩みで検索しますか。

第2回（必須: ページ・競合・制約）

1. 主要なページの URL と役割（CVページ、サービス詳細、料金、事例など）を教えてください。
2. 狙うキーワードで検索結果の上位に出る競合サイトを3〜5件と、事業上の競合（比較されやすい企業・サービス）を教えてください。両者は違っていてかまいません。
3. 下の法規制・表示ルールの一覧のうち、該当しそうなものはありますか。法務や監修の確認フローはありますか。
4. 社内で使えない表現、載せられない情報、使えない素材はありますか。
5. 競合と比べた強みは何ですか。裏付けになる数字・実績・第三者評価はありますか。

第3回（任意: 一次情報・データ・目標）

1. 記事に使える一次情報（自社データ、顧客事例、社内の専門家、検証環境、写真）は何があり、どこまで公開できますか。
2. Search Console、GA4、キーワードツール（Ahrefs、Semrush など）のうち、使えるものと権限を教えてください。
3. 期間を区切った目標と、追っている KPI を教えてください。
4. CMS、更新の担当者と頻度、開発を頼める体制を教えてください。
5. マイクロCV（メルマガ登録、資料ダウンロード、会員登録など）はありますか。

### 公開ページと埋められる欄の対応

| 読むページ | 埋められる欄 | 扱い |
|---|---|---|
| 会社概要・運営者情報 | サイト名、事業内容、運営体制の一部 | 書かれた事実は出典 URL を添えて記入 |
| 主要サービスページ・料金ページ | 商材・価格帯、強み（ページ上の主張）、主要ページ表 | 強みの裏付けはページにある記載だけ。解釈は `[要確認]` |
| 問い合わせ・申込ページ | 主要CVの候補 | CVの定義と GA4 のイベント名はユーザーに確認 |
| よく読まれている記事 | 読者像、検索する場面、一次情報の候補、voice-guide | 読者像は推測なので `[要確認]` |
| フッター、特定商取引法に基づく表記、プライバシーポリシー | 通信販売の有無、法規制の手がかり | 法規制の該当は必ずユーザーに確認 |
| 主要キーワードの検索結果 | 検索上の競合の候補 | Web 検索ツールの結果は参考値として `[要確認]` |

- JavaScript で描画するサイトは、取得した HTML に本文がないことがある。その場合は本文を貼ってもらう。

### voice-guide の抽出手順

1. 記事を選ぶ。Search Console のクリック数や GA4 のキーイベント数が多い記事のうち、ユーザーが「自社らしい」と認める3〜5本にする。広告・PR記事、外部の寄稿、方針が今と違う古い記事、AI の下書きをほぼそのまま公開した記事は外す。
2. 次の項目を記事ごとに拾い、表にまとめる。

   | 項目 | 見るところ | 記入の仕方 |
   |---|---|---|
   | 文体 | 文末 | です・ます / である のどちらか、体言止めの頻度 |
   | 一文の長さ | 本文 | 句点で区切った文の平均と最長の文字数（記事から計測した値） |
   | 読者との距離 | 呼びかけ、一人称 | 「あなた」「皆さん」を使うか、「当社」「私たち」「筆者」のどれか |
   | 表記 | 数字・英字・記号、漢字とかな | 全角半角、「こと／事」などの使い分けを実例で拾う |
   | 用語 | 自社用語、業界用語 | 表記ゆれを並べ、多数派を統一表記の案にする |
   | 見出し | H2・H3 | 長さ、名詞止めか疑問形か |
   | 強調 | 太字、囲み | 1記事あたりの使用数 |
   | 一次情報 | 体験・事例・データ | 誰の体験として書くか、監修者の表示方法 |

3. 記事によって割れる項目は、多数派を案として書き、`[要確認: 記事Aは〜、記事Bは〜]` を付けて選んでもらう。
4. 抽出元にあった AI が書いたような表現は、ルールとして採用しない（[06-writing-editing.md](06-writing-editing.md) の禁止表現リストと照合する）。
5. 記事から読み取れない項目（広告・PR表記、監修者の扱い、社内の禁止表現）は `[要追加: ○○]` のままにする。
6. 良い例／悪い例は、抽出元の記事からユーザーが選んだ一節を出典 URL 付きで引用する。例文を創作しない。

### 業種別の法規制・表示ルール（該当の確認用）

該当するかどうかの判断はユーザー（法務担当や専門家）が行う。Claude は候補と、コンテンツで関係する場面を示すだけにする。

| 法令・ルール | 主に関係するサイト | コンテンツで関係する場面 | 確認先 |
|---|---|---|---|
| 景品表示法（不当表示の禁止: 優良誤認・有利誤認） | 商品・サービスを販売する事業者 | 「No.1」「最安」などの表示、比較記事、料金の表示、口コミの引用 | 消費者庁 |
| 景品表示法のステルスマーケティング規制（2023年10月1日施行） | 第三者（インフルエンサー、アフィリエイター、レビュー記事の書き手）に自社商品の紹介を依頼する事業者 | 依頼したレビュー・紹介記事やアフィリエイト記事で、広告であることを明示しているか | 消費者庁「ステルスマーケティング規制」の告示と運用基準 |
| 薬機法（虚偽・誇大広告の禁止、承認前の医薬品等の広告の禁止など） | 医薬品、医薬部外品、化粧品、医療機器、医薬品的な効能効果をうたう健康食品 | 効能効果の表現、体験談、使用前後の比較 | 厚生労働省「医薬品等の広告規制について」、医薬品等適正広告基準 |
| 医療法の広告規制（医療広告ガイドライン） | 病院、診療所、歯科、美容医療 | 医療機関のウェブサイト、症例写真、体験談、治療内容の説明 | 厚生労働省「医療法における病院等の広告規制について」、ウェブサイト等の事例解説書 |
| 金融商品取引法（広告等の規制） | 証券、投資信託、FX など金融商品を扱う事業者 | 商品の紹介、リスクと手数料の表示、比較・ランキング記事 | 金融庁 |
| 特定商取引法（通信販売の広告表示、誇大広告等の禁止、最終確認画面の表示） | EC、通信販売、定期購入 | 商品ページ・LP の表示事項、「特定商取引法に基づく表記」、申込の最終確認画面 | 消費者庁「特定商取引法ガイド」 |
| その他（健康増進法・食品表示法、業界団体の広告規程や公正競争規約など） | 食品、不動産、士業など | 業界ごとの表示ルール | 所管官庁、各業界団体 |

- 規制の対象の範囲が法令で違う。ステルスマーケティング規制の対象は広告主（商品・サービスを供給する事業者）であり、依頼を受けたインフルエンサー等の第三者は対象外だと消費者庁は説明している。薬機法の虚偽・誇大広告の禁止（第66条）は「何人も」が対象で、広告主だけでなく、記事を書くメディアやアフィリエイターも対象になる。
- メディア側でも、対価を受けた記事は「広告」「PR」などの表示と `rel="sponsored"` で読者と検索エンジンに伝える運用を voice-guide に定める（rel 属性の使い分けは [11-link-building.md](11-link-building.md)、スパムポリシーとの関係は [00-principles.md](00-principles.md)）。
- 該当ありと回答されたら、site-brief の「制約」に法令名、確認フロー、確認者を書き、執筆時に [06-writing-editing.md](06-writing-editing.md) で表現を確認する。被リンク獲得や PR は [11-link-building.md](11-link-building.md) を参照する。

### 更新のタイミング

- 定期: `最終更新日` から6か月たったら見直す。どの依頼でも最初に両ファイルを読み、6か月以上前なら見直しを提案する。
- 事業の変化: 新サービスの開始・終了、CVの定義や GA4 のキーイベントの変更、料金改定、サイトのリニューアル・ドメイン変更・CMS の変更、対象読者の変更、関係する法令やガイドラインの改正、運営体制や担当者の交代。
- 更新の手順: 変わった欄だけ直し、`最終更新日` と更新履歴（日付・更新者・変更内容）を書く。CVの定義や主要ページが変わったら、進行中の施策表の採点をやり直すよう提案する。

## 6. よくある失敗

- テンプレートをスキルフォルダ内で直接編集する: 作業フォルダの `seo/` にコピーしてから記入する。
- 既存の `seo/site-brief.md` を上書きする: `cp -n` でコピーし、既存ファイルがあれば読み込んで変わった欄だけ直す。
- 最初に15問をまとめて聞く: 必須項目から、1回5問以内に分けて聞く。
- 公開ページから推測した読者像や強みを確定値として書く: `[要確認: ○○（根拠: URL）]` を付け、ユーザーの確認を待つ。
- CVの価値や KPI を業界の一般論で埋める: 推測せず `[要追加: ○○]` のまま残す。
- 競合を事業上の競合だけで挙げる、検索上の競合と1つの表に混ぜる: 狙う語の検索結果で上位にいるサイトを3〜5件、事業上の競合とは別に書く。検索上の競合はクエリによって変わる。
- 抽出元の記事の癖をそのまま voice-guide に採用する: [06-writing-editing.md](06-writing-editing.md) の禁止表現リストと照合してから採用する。
- 法規制に該当するかを Claude が断定する: 候補と注意する場面を示し、判断は法務担当や専門家に任せる。
- 良い例／悪い例の例文を創作する: 実際の記事から引用し、出典 URL を付ける。
- セットアップが終わるまで他の依頼を止める: 先にセットアップを行うのは戦略・優先順位付け・執筆・継続運用の依頼で、それもユーザーが先に進めることを選べば暫定で進めてよい（SKILL.md の「使い方の流れ」1）。技術監査や単発の質問はブリーフなしで進め、CVの定義がないと優先度を確定できないことを伝える。
